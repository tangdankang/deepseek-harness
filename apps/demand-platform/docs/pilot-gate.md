# 试点 Go / No-Go 门禁

门禁同时使用平台自动指标和人工证据。缺证据不是通过，而是 `NOT_READY`；任何失败项为 `NO_GO`；全部通过才为 `GO`。

默认门槛：

| 检查项 | 默认门槛 |
|---|---:|
| 连续试点 | ≥5天 |
| 有效交互 | ≥100 |
| 去标识员工 | ≥20 |
| 员工反馈 | ≥20 |
| 反馈响应率 | ≥20% |
| 员工确认解决率 | ≥30% |
| 平均满意度 | ≥4.0/5 |
| 终态集成成功率 | ≥98% |
| 死信任务 | 0 |
| 关键安全事件 | 0 |
| 已确认重复下游工单 | 0 |
| 关键评测通过率 | 100% |
| 真实样本路由准确率 | ≥90% |
| 视觉验收、回滚演练、业务/安全/运维签字 | 全部为是 |
| 多员工合成试点 | 全量写入报告结构校验通过 |

模板 `config/pilot-gate-evidence.example.json` 中所有值故意为 `null`，防止示例文件被误当成真实放行证据。复制到受控位置并附证据链接/签字记录后再运行门禁。门禁报告不能替代公司正式变更审批。

合成试点不能手工写一个 `true` 代替证据。正式执行时向门禁命令传入 `--synthetic-report approved/synthetic-pilot.json`；命令会校验报告必须为全量写入模式、至少20名员工、2个部门、10名写入员工、100次调用，且错误率、跨员工隔离、幂等和重复工单门槛全部通过。
