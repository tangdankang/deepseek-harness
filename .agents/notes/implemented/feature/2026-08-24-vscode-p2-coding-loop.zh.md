# Agent Note: VS Code P2 编码闭环

Status: implemented

[English](2026-08-24-vscode-p2-coding-loop.md) | 中文

## 问题

VS Code 扩展需要基于现有 Host API 提供可用的编码闭环，同时不能把进程、凭据、会话、Skill 或审批权威转移到 Webview。文件审批还需要准确的执行前表示；通用审批提示无法证明操作将要写入什么内容。

## 决策

**Extension Host 持有编排，并向 Webview 发送只用于展示的模型。** 纯事件折叠器校准持久历史与实时 mux 帧，保留 Host 投影和瞬时状态，并在重连或实时事件出现序号缺口后修复已跟踪尾页。校准会持续到订阅基线完整，不会在固定尝试次数后留下无法回答的审批。对话控制器持有会话选择、历史分页、模型、权限、Skill、上下文和待处理审批。CSP Webview 在消息入口校验动作，既不接收进程句柄，也不接收凭据值。助手 Markdown 在 Extension Host 中渲染；用户文本作为文本内容插入。推理事件只暴露忙碌／状态提示，绝不暴露推理文本。

**对话在编辑器工作期间保持可见。** VS Code 1.106 及以上版本把视图容器放在右侧辅助侧边栏，并在视图隐藏时保留 Webview。醒目的新建对话操作和简洁状态固定在可滚动记录上方。运行时、模型、权限和高级配置位于独立的视图内设置页面；页面或窗口重新创建后，提供方 settings 与 SecretStorage 仍然是权威数据。待处理审批显示在记录之后、输入框正上方，并在新请求到达时滚入视野。

**模型可见的编辑器上下文是持久提示词文本。** 扩展把选区、显式文件、有界文件夹清单或有界工作区清单捕获为确定性的 `<dsh-context>` 分区，其中包含 workspace 相对路径和可选的一基行号。上下文与任务正文中的字面结束标签会在组装框架前转义。二进制、无效 UTF-8、单文件超限和总量超限都会明确失败。可移除标签属于草稿状态，只在 Host 接受提示词后清空。开头的 `/skill-name` 保持在上下文分区之前的首个 token，因此现有 Host Skill 注入器可以识别显式调用。

**Skill 创作使用现有文件系统提供方根目录。** 项目骨架位于 `<workspace>/.agents/skills/<name>/SKILL.md`；用户骨架位于 `<DSH_HOME>/skills/<name>/SKILL.md`。名称采用小写 kebab-case，创建操作不覆盖已有文件，VS Code 与 Host 文件系统监听会刷新斜杠目录。扩展不创建 Skill 数据库或远程目录。

**准确文件审阅仅支持客户端可以复现的工具调用。** `write` 使用拟议的完整内容；定向 `edit` 对当前 UTF-8 文件应用唯一的字面替换，新文件则以空的左侧文档表示。审批协调器把预览绑定到文件存在性和摘要。审批请求可能在关联的工具调用仍处于历史校准阶段时到达客户端；Webview 会展示醒目的准备中卡片，协调器则根据后续历史重新尝试，直至生成准确审阅。没有关联信息或无法复现的调用仍然只能拒绝。允许已经变化、二进制、无效、超限、有歧义或不受支持的输入时会关闭式失败；过期预览通过原始 Host 审批请求被拒绝。Shell 卡片展示准确命令、工作目录与理由，同时说明任意命令的影响无法作为 Diff 预测。

**运行时组合排除绕过路径。** `vscode` profile 保留顶层文件系统 `write` 和 `edit` 及 Shell 升级，并禁用无法保留同等顶层调用视图与审批关联的 `str-replace-editor`、subagent 创建、workflow、Ralph 和 Code Mode 路径。权限选择继续使用现有三种 preset 与持久 `/permission` 投影。

**运行时启动必须具有项目目录。** 显式 `dsh.runtime.cwd` 优先于第一个已打开的工作区文件夹。两者都不存在时，扩展会提示用户先打开文件夹，不再从 VS Code 安装目录启动；该目录既不是正确的工作区，扫描也可能很慢。

## 考虑过的替代方案

**复用浏览器 Cordis UI 外壳。** 不采用，因为这会向本地编辑器集成加入浏览器运行时所有权和第二套客户端架构。VS Code Webview 保持为 Host 协议上的渲染组件。

**在会话日志之外存储上下文附件。** 不采用，因为持久事件将无法重建模型请求，恢复后的对话也会隐藏模型实际收到的内容。

**依据名称与参数批准所有修改工具。** 不采用，因为组合或嵌套调用方可能缺少准确的最终文件内容，使显示的决定弱于真正执行的操作。

**为 Shell 渲染推测性 Diff。** 不采用，因为任意命令可能以静态客户端无法推导的方式影响文件、进程和外部系统。展示准确命令才是真实的审批表示。

## 验证

纯测试覆盖重复历史修复、实时序号缺口恢复、会话投影、记录渲染、上下文限制与持久文本、Skill 根目录与不覆盖创建、准确 Diff 生成、过期拒绝、权限 mutation（变更）和中文右侧栏 Webview。无密钥组装流程快照通过运行时管理器启动真实 stdio 夹具进程，并证明会话恢复、上下文与 Skill 持久化、审批请求与工具调用乱序到达时的校准、工具生命周期、拒绝不写入、一次性允许和推理脱敏。已构建 profile 冒烟启动真实 `vscode` bundle，并执行 Host 配置、Skill 发现与提示词准入及会话 API。可复用手工教程已在真实提供方与 Extension Development Host 上通过验收，覆盖拒绝、陈旧 Diff 保护、一次性允许、权限切换、取消与重启恢复。

## 结果

P2 支持经过审阅的本地编码任务，同时保留 Host 会话作为持久权威。草稿上下文不会恢复；任意 Markdown 资源无法在 Webview CSP 下加载。Diff 审阅支持该 profile 组合的准确 `write` 与字面 `edit` 请求；其他修改工具必须先提供同等可复现的执行前视图，才能加入 profile。Shell 审批是显式的，但不提供事务回滚，也不预测文件系统影响。
