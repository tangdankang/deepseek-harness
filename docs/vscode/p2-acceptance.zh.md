# VS Code P2 新手验收教程

[English](p2-acceptance.md) | 中文

本教程面向第一次使用 VS Code 命令、Extension Development Host 和 DSH 的验收者。完成后，你会在一个仓库外的临时文件夹中验证完整 P2 编码闭环，不会拿正在开发的仓库文件做写入试验。

状态：完整流程已于 2026-08-25 通过用户验收，后续继续作为已验收 P2 基线的可复用回归流程。

## 开始前先读

- 每个步骤都有“怎么做”“怎样算通过”和“遇到问题怎么办”。按顺序执行；某一步失败时先停在该步，不要带着错误继续。
- 只在 `E:\E_AI\DSH\vscode-p2-acceptance` 临时文件夹内批准写入。审批卡片显示其他路径或看不懂的命令时，选择**拒绝**。
- 模型配置需要你自己的 OpenAI 兼容提供方地址、模型 ID 和已经轮换的 API key。API key 只输入到密码框，不要写进文件、VS Code settings JSON、截图或验收报告。
- 按键写法 `Ctrl+Shift+P` 表示按住 `Ctrl` 和 `Shift`，再按一下 `P`，然后松开。

### “运行某个命令”到底是什么意思

VS Code 的 `Ctrl+P` 和 `Ctrl+Shift+P` 是两个不同功能。`Ctrl+P` 查找文件；把命令名称输入这里，常会得到“没有匹配的结果”。`Ctrl+Shift+P` 才会打开命令面板，顶部输入框左侧会有一个 `>`。

以后看到“运行 **DSH：某命令**”，完整操作都是：按 `Ctrl+Shift+P`，输入命令名称，看到结果后单击该结果或按 `Enter`。如果界面已有同名按钮，直接点击按钮也可以。

你截图中的顶部框可以先按 `Esc` 关闭。配置模型时直接点击右侧 DSH 面板右上角的齿轮按钮，再点击 **配置并保存模型**；它和运行 **DSH：配置 OpenAI 兼容模型** 是同一个操作。

## 1. 打开普通 VS Code 和仓库

### 怎么做

1. 关闭截图中正在显示的顶部搜索框；按一次 `Esc` 即可。当前 VS Code 窗口可以先保留。
2. 从 Windows 开始菜单打开一个普通的 **Visual Studio Code** 窗口。
3. 点击顶部菜单 **文件（File）**，再点击 **打开文件夹（Open Folder）**。
4. 选择 `E:\E_AI\DSH\deepseek-harness-myPcVs`，然后点击 **选择文件夹**。
5. 如果出现“是否信任此文件夹”的提示，确认路径完全等于上面的仓库路径后，选择信任。

### 怎样算通过

左下角状态栏能看到 `master` 分支，左侧文件资源管理器能看到 `apps`、`docs` 和 `packages` 等目录。

### 遇到问题怎么办

如果打开的是单个文件而不是整个文件夹，重新使用 **文件 → 打开文件夹**。如果路径不同，不要继续构建，把实际路径发给开发者确认。

## 2. 构建扩展并创建临时测试文件夹

### 怎么做

1. 在刚打开的普通 VS Code 中，点击顶部菜单 **终端（Terminal）**，再点击 **新建终端（New Terminal）**。
2. 窗口底部会出现以 `PS E:\E_AI\DSH\deepseek-harness-myPcVs>` 开头的 PowerShell 终端。
3. 依次复制下面五条命令。每次只复制一行，粘贴到终端后按 `Enter`，等终端重新出现 `PS ...>` 提示符，再执行下一行。

```powershell
pnpm run build:lib:host
pnpm --filter @deepseek-ai/dsh-vscode run build
New-Item -ItemType Directory -Force -Path "E:\E_AI\DSH\vscode-p2-acceptance" | Out-Null
Set-Content -LiteralPath "E:\E_AI\DSH\vscode-p2-acceptance\value.txt" -Value "alpha" -NoNewline
code --new-window --extensionDevelopmentPath="E:\E_AI\DSH\deepseek-harness-myPcVs\apps\vscode\extension" "E:\E_AI\DSH\vscode-p2-acceptance"
```

不要只按 `F5` 启动这次验收窗口。新打开的 Extension Development Host 必须把 `vscode-p2-acceptance` 显示为当前文件夹；只有 Welcome 欢迎页的窗口没有项目目录，DSH 会要求先打开文件夹，不再从 VS Code 安装目录启动。

4. 最后一条命令会再打开一个 VS Code 窗口。后续验收只操作这个新窗口；原来的仓库窗口保持打开，最后重启测试时还会用到它。

### 怎样算通过

两条构建命令都结束并回到 PowerShell 提示符，没有出现 `ERR_PNPM` 或构建失败。新窗口的文件资源管理器只显示临时文件夹内容，其中有一个 `value.txt`，打开后内容是 `alpha`。

### 遇到问题怎么办

如果终端提示找不到 `pnpm`、`code` 或某个路径，停止验收并把完整错误截图发给开发者。如果构建只有黄色 warning 但最终回到提示符，可以继续；红色 error 或命令一直不结束则不要继续。

6. 确认 **Dsh › Runtime: Cwd** 保持空白。关闭设置页签，回到右侧 **DeepSeek Harness** 面板。

### 遇到问题怎么办

## 4. 启动 DSH

1. 点击 DSH 面板顶部的蓝色 **启动**按钮。
2. 等待状态依次从**正在启动……**变成**已连接**；通常需要几秒。

## 5. 配置模型

### 怎么做

1. 点击 DSH 面板右上角的齿轮按钮，进入独立的 **DSH 设置**页面，再点击**配置并保存模型**。不要使用截图中显示“没有匹配的结果”的输入框。
2. 配置向导共有六个输入框。每次填完后按 `Enter` 进入下一项：

   1. **Provider route**：填一个只含小写字母、数字和连字符的本地名称，例如 `acceptance-provider`。
   2. **Provider name**：填显示名称，例如 `Acceptance Provider`。
   3. **API base URL**：粘贴提供方文档给出的 OpenAI 兼容 API 地址，通常以 `/v1` 结尾。不要凭空猜地址。
   4. **Model ID**：填提供方接受的准确模型 ID。
   5. **Model name**：填你希望在选择器中看到的名称；不确定时可以和 Model ID 相同。
   6. **API key**：粘贴已经轮换的新密钥。输入会显示为圆点，这是正常现象。

3. 完成第六项后等待 DSH 自动重启并重新显示**已连接**，再点击**完成并返回对话**。

### 怎样算通过

右下角出现类似“已保存模型 `acceptance-provider/模型ID`，新对话会使用此模型”的通知，DSH 随后重新显示**已连接**。尚未创建对话时，设置页的模型选择框可以暂时显示**尚无可用模型**；第六步创建并选中对话后才会加载模型目录。

### 遇到问题怎么办

如果点击**配置并保存模型**没有反应，先确认状态为**已连接**，再点一次。如果必须使用命令面板，按 `Ctrl+Shift+P`，输入 `DSH：配置 OpenAI 兼容模型`；顶部必须有 `>`。仍然没有结果时，说明操作的不是装有开发扩展的新窗口，回到第二步重新启动。看到配置成功通知后不要因为**尚无可用模型**而重复输入 API key。
