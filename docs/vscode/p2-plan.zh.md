# VS Code P2 计划：最小可用开发闭环

[English](p2-plan.md) | 中文

状态：已批准。D1–D7 与完整计划已经通过；P2.1 已于 2026-08-24 通过用户验收，P2.2 尚未开始。

## 目标

P2 在 VS Code 内交付第一个完整编码闭环：用户创建或恢复 DSH 会话，携带编辑器上下文与可选 Skill 发送任务，观察模型读取和分析项目，审阅每项拟执行的文件修改或高权限命令，允许或拒绝操作，查看工具结果，并在重启 VS Code 后恢复会话记录。

## 当前阶段

P2.1 提供安全的 OpenAI 兼容提供方引导，以及已经批准的三种权限选择。已验收的阶段结果记录在[项目总结](README.md)中。P2.2 是下一个工作包，仅在用户明确要求后开始。

## 验收边界

只有 DSH 能够通过扩展完成一个小型真实仓库修改，而不只是讨论修改时，P2 才算通过验收。默认模式会在文件修改或沙箱升级前要求一次性确认。拒绝后目标保持不变；批准只适用于已经展示的那一次操作；所有事件都保留在持久会话记录中。

## 范围

### 范围内

- 使用 VS Code 主题变量、键盘行为、无障碍标签和内容安全策略的 VS Code Webview 对话界面。
- 调用会话列表、创建、历史、提示词、取消、模型选择、审批应答、Skill 列表等 Host API，并使用实时更新所需的 mux/host 流。
- 展示流式助手文本、不暴露思维链的推理状态摘要、工具调用/结果卡片、运行状态、终止错误与重连校准。
- 收集当前选区、当前文件、Explorer 文件、Explorer 文件夹与工作区上下文，并在适用时显示来源路径和行号范围。
- 会话列表、创建、切换、历史分页，以及基于现有 DSH 持久化存储的冷会话恢复。
- 项目级与用户级 Skill 发现、目录展示、`/skill-name` 补全、显式调用、热刷新，以及创建或打开 Skill 位置的命令。
- 只读、确认修改、工作区自动写入三种权限选择；新建 VS Code 会话默认选择确认修改。
- 文件工具执行前的 Diff 审阅、需要沙箱升级的 Shell 工具命令审阅、一次性允许/拒绝应答，以及可见的最终结果。

### 范围外

- 整个轮次级的多文件事务、批量接受/拒绝、自动检查点，以及批准修改后的回滚。
- 记住审批、始终允许规则、不受限宿主访问、交互式 PTY 与后台任务管理。
- 富文本 Skill 编辑器、市场安装、远程 Skill 提供方与递归嵌套 Skill 发现。
- 符号搜索、诊断集成、语言服务器编排与语义代码探索，这些保留到后续阶段。
- Git 暂存、提交、分支与冲突流程，这些保留到后续阶段。
- 远程 DSH 连接、多运行时所有权，以及整体复用浏览器 Cordis UI 外壳。

## 已核实的技术基线

| 现有能力 | P2 用途或缺口 |
| --- | --- |
| 逐行 JSON-RPC 请求/响应 | 在不改变既定传输方案的前提下，将 P1 客户端从仅握手扩展为类型化 Host API 调用。 |
| `session.list`、`session.create` 与 `session.history` | 无需增加第二套持久化，即可提供会话发现、创建、分页与冷会话恢复。 |
| `events.mux` 与 `events.host` | 承载持久会话事件、工具视图、队列状态、运行状态、审批请求与传输错误；stdio 载体需要实现长驻流订阅。 |
| `session.prompt` | 发送文本和图片部分，并分发宿主斜杠命令；文件上下文需要确定性文本渲染，权限切换可以复用 `/permission`。 |
| `skill.list` 与文件系统 Skill 提供方 | 已能发现项目级和用户级 Skill、监控目录变化，并支持确定性的 `/skill-name` 注入；VS Code 还需要目录和创建 UI。 |
| 文件工具调用视图 | `write` 与 `edit` 会在执行前发布待处理 Diff 意图；VS Code 必须通过审批 `callId` 关联意图，并读取当前工作区内容生成精确预览。 |
| 审批应答通道 | Host mux 帧已经承载一次性审批请求，`api.respond` 接受 `allowed-once` 或 `rejected`；stdio 客户端还需实现应答路径和失败时关闭的 UI 生命周期。 |
| 权限 preset 与投影 | DSH 会持久化每个会话的沙箱和审批设置，但 `vscode` profile 需要提供互相独立的只读、确认修改与工作区写入产品选项。 |
| `settings.*`、凭据与模型选择 | 已支持脱敏设置视图、自定义提供方元数据与会话级模型选择；VS Code SecretStorage 仍是建议的密钥所有者。 |

## 建议设计

### 运行时与协议客户端

P1 运行时管理器继续管理一个子进程。其协议客户端增加类型化单次调用、长驻 mux/host 订阅、服务端请求应答、请求取消、进程退出时拒绝未完成请求，以及重连校准。Host API schema 继续作为 wire 权威；VS Code 层不创建平行协议。

### 对话与会话展示

对话记录与输入框由 Webview 承载，因为现有 Tree View 不适合流式 Markdown、审批控件和 Diff 卡片。Extension Host 管理 DSH I/O，并把验证后的视图模型发送给 Webview；Webview 不接触进程句柄或提供方凭据。P2 会在不引入浏览器 Cordis 外壳的前提下尽量复用纯事件折叠与展示逻辑。

连接后，扩展读取 `session.list`；上次本地活动会话仍存在时优先选择它，然后加载最新一页历史。mux 订阅先于校准启动，以避免事件缺口；使用订阅序号与历史序号消除重叠。较早页面按需加载；用户发送下一条提示词时，冷会话通过现有 Host 路径恢复。

### 上下文表示

每个选中上下文都会变成确定性文本分区，其中包含来源类型、工作区相对路径、可选行号范围和捕获文本。渲染文本进入 `session.prompt`，因此模型可见输入会持久化在用户消息中。上下文标签可在发送前移除；文件夹只展开为有界文件清单；二进制文件会被拒绝；内容超过限制时显示明确拒绝，不做静默截断。

### Skill 体验

输入框根据活动会话查询 `skill.list`，并提供 `/skill-name` 补全。用户选择或手动输入的、以空白分隔的 Skill 名称会保留在用户消息中，DSH 使用现有机制确定性注入完整 Skill 内容。目录变化会刷新选择器，不需要重启运行时。

**创建项目 Skill** 会在 `<workspace>/.agents/skills/<name>/SKILL.md` 为仓库拥有的工作流生成骨架。**创建用户 Skill** 会在 `<DSH_HOME>/skills/<name>/SKILL.md` 为个人跨项目工作流生成骨架。两个命令都校验 kebab-case 名称，拒绝已经存在的目标，打开新文件供编辑，并且绝不覆盖 Skill 资源。**打开 Skills 文件夹** 会展示两个位置，不引入第二套 Skill 存储。

### 权限模式

`vscode` profile 提供三种产品选择，并把选中值记录到现有会话权限事件中。

| 模式 | 沙箱与审批行为 | 用户体验 |
| --- | --- | --- |
| 只读 | `read-only` 且禁用审批 | 读取和非修改工具可以运行；所有升级都会失败，不显示允许操作。 |
| 确认修改 | `read-only` 且启用一次性审批 | 文件修改显示 Diff，Shell 升级显示准确命令；每项操作都等待允许一次或拒绝。 |
| 工作区写入 | `workspace-write`，只有更宽访问才需要审批 | 工作区内修改自动运行；更宽访问仍需要一次性审批。 |

确认修改是 VS Code 默认值。选择器通过现有权限命令改变活动会话，并通过设置 API 修改新建会话的默认值。UI 始终显示会话的实际值，不会假设保存的默认值也改变了现有会话。

### Diff 与审批流程

当审批帧通过文件工具 `callId` 指向某个调用时，Extension Host 会把它与该待处理调用的 `card: diff` 视图连接起来，根据会话工作区解析路径，读取当前文件，并生成 VS Code Diff 预览。新建文件使用空的左侧文档；定向编辑把拟执行替换应用到当前左侧文档；整文件写入使用拟写入内容作为右侧文档。审批卡片显示原因、受影响路径，以及**允许一次**或**拒绝**控件。

文件在等待审批期间发生变化时，扩展会让预览失效并拒绝过期审批。应答之后，DSH 的文件系统观察策略继续执行最终的过期写入检查。拒绝会应答 Host 请求，并且不调用修改操作。成功后，待处理卡片会被持久化的已应用 Diff 视图替换。

P2 智能体可见的所有修改路径都必须经过这项策略。无法提供执行前 Diff 或一次性审批的修改工具，会从 VS Code 智能体组合中受到限制，直到具备相同行为。P2 禁用 Code Mode，防止嵌套修改调用绕过顶层展示元数据。

Shell 升级有所不同：UI 可以展示准确命令、工作目录、原因与请求权限，但无法预测所有文件系统影响。审批文字会明确说明该限制。只读模式拒绝 Shell 升级；确认修改模式允许执行一条已批准命令；工作区写入模式遵循所选沙箱策略。

### 提供方与凭据配置

建议以 VS Code SecretStorage 作为密钥唯一来源，非机密提供方元数据通过 DSH settings 保存。启动运行时时，扩展读取这一项具名机密，仅把对应的显式凭据变量加入已经清理的子进程环境；DSH 子进程会移除继承的疑似凭据变量。密钥不会进入扩展设置、命令参数、诊断、会话事件、快照或本文档。真实提供方验收前，必须先轮换此前已经披露的密钥。

## 验证与验收

### 自动化证据

- 单元测试覆盖协议分帧、事件顺序、历史/实时重叠、重连、取消、审批关联与失败时关闭的释放流程。
- 权限测试证明只读拒绝、确认修改的一次性决策、工作区自动写入，以及拒绝无法展示的修改工具。
- Diff 测试覆盖新建、定向编辑、整文件覆盖、拒绝、文件过期失效、已应用结果替换与 Windows 路径。
- Skill 测试覆盖项目/用户发现、优先级、斜杠调用、热刷新、名称验证、已存在目标拒绝与准确骨架内容。
- 无密钥的组装快照通过可运行示例记录会话创建、上下文与 Skill 提交、流式文本、一次拒绝修改、一次批准修改、工具生命周期行、取消与恢复历史。
- 已安装的 Extension Development Host 测试激活真实扩展，并验证 Webview 消息、VS Code Diff 文档、Skill 命令、审批应答与权限切换。
- 定向 typecheck、lint、build、包 invariant、运行时闭包、翻译配对与文档门禁覆盖 P2 差异；已经接受的仓库基线单独保留。
- 真实提供方定向任务仅在密钥完成轮换并通过批准的路径存储后，使用已配置的自定义 OpenAI 兼容路由。

### 手工验收流程

1. 在全新的 Extension Development Host 中打开仓库，确认 DSH 状态变为已连接。
2. 通过安全输入配置自定义提供方，创建会话，并确认默认选择**确认修改**。
3. 从扩展创建一个项目 Skill，加入一条可观察的编码规则，输入 `/skill-name`，确认该 Skill 出现在任务流程中。
4. 从编辑器或 Explorer 添加一个选区和一个文件，核对路径与行号信息，然后发送一个小型代码修改任务。
5. 确认助手文本逐步流出，并且读取/搜索工具调用显示运行中与已结束状态。
6. 第一次出现文件修改提案时，检查 VS Code Diff，选择**拒绝**，确认文件保持不变。
7. 再次请求修改，检查 Diff，选择**允许一次**，确认只应用了展示的文件修改。
8. 批准一条已经展示的测试命令，确认其输出出现，并核对命令卡片明确说明终端副作用无法被预测为 Diff。
9. 把会话切换到**只读**，再次请求修改，确认操作失败且不显示允许按钮。
10. 仅在测试夹具中切换到**工作区写入**，请求一次工作区内编辑，确认它自动运行，而工作区外访问仍会询问或失败。
11. 重启 Extension Development Host，选择之前的会话，确认会话记录、权限值、Skill 证据、Diff 与决策得到恢复且没有重复事件。

## 停止条件

已批准的计划每次只授权一个工作包。每个工作包在报告阶段结果后停止，等待用户验收通过，再开始下一个工作包。P2.1 验收已经解除本阶段阻塞；用户明确要求开始之前，P2.2 仍保持未启动状态。
