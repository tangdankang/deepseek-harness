管理摘要

项目已经越过“能够连接模型”的原型阶段，具备可实际完成小型开发任务的最小产品闭环。用户可以在 VS Code 右侧栏创建或恢复会话，携带编辑器上下文和 Skill 发起任务，在执行前审阅文件 Diff 或 Shell 命令，并在拒绝、一次性允许和不同权限之间保持明确控制。

验收过程中暴露的易用性与恢复问题已经进入产品基线：模型配置持久化、右侧栏常驻、中文界面、独立设置页、醒目的新建对话、底部审批、历史缺口自动修复、Skill 斜杠补全，以及无工作区时的直接启动诊断。

开发闭环

  • 会话创建、选择、分页历史、流式 Markdown、工具卡片与取消。
  • 选区、文件、文件夹和工作区上下文，带路径、范围与大小限制。
  • 项目级和用户级 Skill，支持创建、发现、刷新、补全与显式调用。
  • 准确文件 Diff、Shell 命令披露、拒绝与一次性允许。

可靠性与恢复

  • 扩展持有本地 stdio Host，建立类型化请求、流与取消。
  • 历史与实时事件持续校准，序号缺口会自动补齐。
  • 模型、权限、会话和凭据在视图切换与窗口重开后恢复。
  • 没有工作区文件夹时拒绝从 VS Code 安装目录启动。

用户体验

  • DSH 位于右侧辅助侧边栏，与代码编辑区并排使用。
  • 核心运行和对话控件中文化，配置集中在独立设置页。
  • 新建对话和审批状态具有明确视觉层级。
  • 审批卡片位于记录底部并自动滚入视野。

安全属性

  • API 密钥保留在 VS Code SecretStorage，不进入 settings、日志或快照。
  • Webview 不持有进程、文件系统或凭据权威。
  • 陈旧 Diff、二进制、无效 UTF-8、超限和歧义输入关闭式失败。
  • 无法提供同等审阅证据的修改工具路径不进入组合。

P2 后建议路线

A

稳定性与上手体验

消除手工路径、完善首次启动、收敛设置与恢复行为、改进长会话性能，并把用户验收中的关键路径固化为稳定回归。

B

分发与复用

生成可安装扩展，定义版本与支持矩阵，提供无凭据配置迁移、示例项目、Skill 模板和面向新用户的安装教程。

C

产品改进

优先改善导航、审批、诊断、无障碍、中文化和恢复体验；在这些基础稳定后，再评估 Git、语义搜索、远程运行时或多智能体等更大能力。

下一阶段应先明确目标用户与分发方式，再决定安装包、运行时捆绑和配置迁移方案。任何复用机制都必须保持 SecretStorage 的凭据所有权与修改前准确审阅。
