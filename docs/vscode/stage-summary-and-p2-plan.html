P2 目标：最小可用开发闭环

P2 让用户在 VS Code 中完成“提出需求 → 添加上下文或 Skill → DSH 分析和读取 → 预览文件 Diff 或终端命令 → 允许或拒绝 → 查看执行结果 → 重启后恢复会话”的完整闭环。

范围内

  • 侧边栏聊天、会话创建/恢复、流式文本、工具状态、取消与重连。
  • 当前选区、文件、Explorer 文件/文件夹和工作区上下文。
  • 项目级与用户级 Skill 的创建、列表、斜杠调用和热刷新。
  • “只读”“确认后更改”“工作区可写”三种权限选择，默认“确认后更改”。
  • 文件操作执行前显示准确 Diff，并允许或拒绝本次操作。
  • 终端操作执行前显示准确命令、工作目录和风险提示，并允许或拒绝。

明确不做

  • 整轮多文件批量接受、检查点和自动回滚。
  • 永久记住批准、无限制权限、PTY 终端和后台任务管理。
  • 完整 Skill 编辑器、市场、远程 Skill 和嵌套 Skill。
  • LSP、诊断、Git 暂存、提交、分支和冲突处理。
  • 远程 DSH、多运行时与完整复制浏览器 Cordis UI。

已经批准的 7 项决策

D1
密钥存储：建议 VS Code SecretStorage只把扩展管理的具名密钥显式注入自有 DSH 子进程；非机密提供方配置写入 DSH settings。真实验收前轮换已披露密钥。
D2
默认权限：建议“确认后更改”DSH 可以分析和读取；每次文件更改或终端命令必须在执行前由用户允许或拒绝。
D3
权限选择：建议只提供三种模式“只读”“确认后更改”“工作区可写”；P2 不暴露无限制权限，也不提供永久批准。
D4
上下文格式：建议确定性文本分区把来源、相对路径、行号与捕获内容随普通提示词持久化，并使用严格大小限制。
D5
Skill 范围：建议项目级和用户级支持发现、列表、斜杠调用、热刷新，以及不会覆盖已有文件的基础创建命令。
D6
审批展示：文件显示准确 Diff，终端显示准确命令终端命令可能产生无法预先枚举的副作用，界面必须明确提示这一差异。
D7
完成证据：建议三层验收无密钥快照 + 真实 Extension Host + 一次真实提供方定向测试，并由用户执行下方 11 步中文流程。
D1–D7 已全部批准。停止条件仍然有效：每个工作包完成后先返回阶段结果，等待用户验收，再进入下一个工作包。P2.2 仅在用户明确要求后开始。

P2.1 中文手工验收流程

  1. 先轮换此前已经披露的 API 密钥；本次验收不得继续使用旧密钥。
  2. 重新构建 Host 和 VS Code 扩展，在全新 Extension Development Host 中打开仓库并启动 DSH。
  3. 执行 DSH: Configure OpenAI-compatible Model，输入非机密提供方信息与轮换后的新密钥。
  4. 确认运行时自动重启，侧边栏显示所选提供方／模型，并显示默认权限 confirm-changes。
  5. 执行 DSH: Select Default Permission，依次验证三种选项均可选择，最后恢复为“确认后更改”；侧边栏应立即显示结果。
  6. 打开 DeepSeek Harness 输出，确认没有密钥；重启 Extension Development Host，确认模型与默认权限仍可恢复。P2.1 尚无聊天输入框，这是预期结果。

P2 完整阶段计划中的中文手工验收流程

  1. 在全新 Extension Development Host 打开仓库，确认 DSH 状态变为已连接。
  2. 安全配置模型，确认默认权限为“确认后更改”，且输出中不出现密钥。
  3. 创建一个项目级 Skill，确认文件位置正确，并通过 /skill-name 调用。
  4. 添加选区或文件上下文并发送中文开发任务，核对来源、路径和行号。
  5. 确认助手文本逐步流出，读取类工具卡片显示运行中和已结束状态。
  6. 让 DSH 提议一个小文件更改，核对执行前 Diff，选择拒绝并确认工作区未变化。
  7. 再次提出同一更改，核对 Diff 后允许，确认只应用所展示的文件操作。
  8. 让 DSH 运行一个安全测试命令，核对命令与工作目录，并确认界面提示无法预知全部副作用。
  9. 切换“只读”，确认文件更改和终端命令均不能执行。
  10. 在专用测试目录切换“工作区可写”，确认工作区内操作符合策略，越界操作仍需一次性批准。
  11. 重启 Extension Development Host，恢复会话，确认消息、工具事件、审批结果和 Skill 引用完整且不重复。
